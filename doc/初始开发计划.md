# 工具盒子 — 初始开发计划

## 项目定位

功能性工具集合桌面应用。每个工具以插件方式接入，与核心低耦合。

## 技术栈

- 前端：Vue 3 + Tailwind CSS v4 + Vite
- 后端：FastAPI（Python）
- 桌面壳：Electron
- 项目组织：Monorepo（backend/ + frontend/ + electron/ 三个子目录）

## 架构总则

### 低耦合原则

1. **后端**：每个工具是一个独立模块，通过自动注册机制挂载到主应用。新增工具不修改核心代码。
2. **前端**：每个工具是一个独立页面，通过配置化的路由数组注册。布局组件驱动工具列表渲染。
3. **Electron**：不感知具体工具，只负责管理后端子进程生命周期和打开前端窗口。

### 核心约定

- 后端每个工具模块必须暴露固定格式的元信息（名称、路由前缀、图标），供注册中心识别。
- 前端工具路由统一在一个配置文件中管理，新增工具时追加一条记录。
- 前后端通过约定好的 API 路径模式通信：`/api/v1/tools/{tool-name}/...`

## 关键设计决策

### 后端工具注册机制

- 主应用启动时自动扫描指定目录下的工具模块
- 每个工具模块通过固定导出向注册中心声明自身信息
- 注册中心负责挂载路由到主应用

### 前端工具路由机制

- 工具路由集中配置在一个数组文件中
- 布局组件读取该配置渲染左侧工具列表
- 每个工具页面懒加载

### 临时文件管理

- PDF 转换产生的临时文件集中存放
- 定期后台清理过期文件

### Electron 与后端进程管理

- 主进程启动时通过子进程拉起后端
- 通过健康检查接口确认后端就绪
- 窗口关闭时发送终止信号给后端子进程
