# 工具盒子 项目结构导航文档

项目根目录：当前 Git 仓库根目录（`ROOT`）

> 本文档用于按问题类型快速定位当前代码文件；文件功能以当前仓库实现为准。

## 路径与跨设备约定

本文档正文统一使用仓库相对路径，`ROOT` 表示当前 Git 仓库根目录，不绑定任何设备的盘符或用户目录。当前已知开发位置如下：

| 设备环境 | 本机项目根目录 | 使用说明 |
|---|---|---|
| macOS（当前工作区） | `/Users/mima1234/Desktop/code/tools` | AI 可直接从当前仓库根目录按相对路径读取 |
| Windows（另一开发设备） | `H:/code/tools` | 切换到该设备后继续使用相同仓库相对路径 |

**AI 读取规则**：

1. 先确认当前工作目录位于 `ROOT`；正文中的 `frontend/...`、`backend/...` 等路径均相对于 `ROOT`。
2. 优先使用仓库相对路径，不能把另一台设备的绝对路径当作当前路径。
3. 工具必须使用绝对路径时，可通过只读命令 `git rev-parse --show-toplevel` 获取当前设备的 `ROOT`，再拼接文档中的相对路径。
4. 两台设备只需保持 Git 仓库结构和分支同步；设备目录变化时只更新本节映射，不修改正文文件路径。

## 快速定位

| 需求或问题 | 优先读取文件 | 选择依据 |
|---|---|---|
| 开发启动、依赖环境和模型下载边界 | `start-dev.bat`、`start-dev.command`、`electron/dev-runner.js` | 两个平台启动脚本只准备 Node/Python 依赖；Electron 启动器负责编译和进程协同，模型下载不在启动阶段执行 |
| MinerU 模型状态、手动下载或取消 | `backend/app/api/v1/settings.py`、`backend/app/services/model_manager.py`、`frontend/src/views/settings/Settings.vue` | 分别定义设置 API、下载任务和设置页状态交互 |
| PDF 深度解析未准备模型 | `backend/app/services/tools/pdf_to_markdown_deep.py`、`backend/app/services/model_manager.py` | 深度解析只检查模型就绪状态；模型下载由模型管理服务负责 |
| 打包环境执行 MinerU | `backend/packaging/server.py`、`backend/packaging/backend.spec` | PyInstaller 入口和模型下载/转换运行时入口在此处定义 |
| 思维导图解析、节点编辑、XMind 导入导出或图像导出 | `frontend/src/features/mindmap/components/MindMapViewer.vue`、`frontend/src/features/mindmap/core/utils/markdown.ts`、`frontend/src/features/mindmap/core/utils/xmind.ts`、`frontend/src/features/mindmap/core/utils/export.ts` | 分别承载地图交互、Markdown 结构转换、XMind 文件适配和 SVG/PNG 导出 |
| 思维导图正式入口和导航 | `frontend/src/views/tools/MindMap.vue`、`frontend/src/router/index.ts`、`frontend/src/components/layout/AppSidebar.vue` | 工具页面、静态设置路由和侧边栏入口在此处注册 |
| 公共表单组件和下拉框 | `frontend/src/components/common/BaseSelect.vue`、`frontend/src/components/common/types.ts` | 统一自定义下拉框的触发器、选项弹层、选中状态、键盘操作和 ARIA 交互 |
| Markdown 转 PDF 的 Word 链路转换 | `backend/app/services/tools/markdown_to_pdf.py`、`backend/app/utils/libreoffice.py`、`frontend/src/views/tools/MarkdownToPdf.vue` | 分别负责 DOCX 中间文件、LibreOffice 转换和页面参数交互 |
| PDF 前后端联调验证 | `frontend/tests/pdf-integration.spec.ts` | 覆盖标准模式、深度模式和重新上传流程 |
