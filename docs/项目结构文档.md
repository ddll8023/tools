# 工具盒子项目结构

本文说明当前实现的运行边界、目录职责与业务模块，是按任务定位代码的入口，不是目录重构方案或未来架构设计。

## 阅读方式与范围

- 路径基准：以 `backend/`、`frontend/`、`electron/` 等顶层目录开头的为仓库根相对路径；模块文档「公共与跨模块引用」表中省略前缀的写法以 [公共记录](modules/shared.md) 的路径约定为准。
- 覆盖：`electron/`（主进程与更新）、`frontend/`（渲染进程）、`backend/src/toolbox_backend/`（FastAPI 后端）、`backend/packaging/`（打包入口与 USB 原生依赖清单）、`scripts/`（构建脚本）、`.github/workflows/desktop-release.yml`。
- 排除：`node_modules/`、`backend/.venv/`、`electron/*.js`（编译产物）、`build/`、`release/`、`backend/resources/` 下的模型二进制（本地前置资源，未纳入版本控制）。
- 阅读顺序：本页 → 目标模块 → 模块实际引用的 [公共记录](modules/shared.md)。
- 文件唯一归属；模块引用公共记录不改变其归属，逻辑模块不等同物理目录。

## 技术栈

| 层 | 事实来源 | 当前实现 |
| --- | --- | --- |
| 桌面外壳 | `package.json`、`electron/tsconfig.json` | Electron 主进程用 TypeScript 编写，`tsc` 编译为同目录 `electron/*.js`（CommonJS）后由 Electron 直接加载 |
| 前端 | `frontend/package.json`、`frontend/vite.config.ts` | Vue 3 + TypeScript + Pinia + Vue Router（hash 模式）+ Tailwind CSS v4，Vite 构建；Markdown 渲染用 `marked`/`highlight.js`，公式用本地 `@mathjax/src` |
| 后端 | `backend/pyproject.toml`、`backend/src/toolbox_backend/main.py` | FastAPI + Uvicorn，全部接口 POST，统一 `{code,message,data}` 响应壳；无数据库，状态落在用户数据目录的文件与内存 |
| 文档转换 | `backend/pyproject.toml` | PyMuPDF、python-docx、pdf2docx、MinerU、reportlab、Pillow、ONNX Runtime、LibreOffice 外部进程 |
| 打包 | `package.json` build 段、`backend/packaging/backend.spec` | electron-builder 出 dmg/zip/nsis；后端由 PyInstaller 打成 `toolbox-backend` 可执行目录，作为 extraResources 随包 |

具体版本以各 `package.json`、`pyproject.toml`、`uv.lock` 为准，本文不复制版本清单。

## 运行与调用边界

```text
Electron 主进程 (electron/main.ts)
├─ 子进程: 后端 toolbox-backend / uv run uvicorn   127.0.0.1:18740  /api/v1
│   └─ 子进程: USB worker (--toolbox-usb-worker)    stdio JSON 行协议
│   └─ 子进程: MinerU CLI (--toolbox-mineru*)       文件与退出码
│   └─ 线程:   局域网数据面 uvicorn                  0.0.0.0:18751 浏览器页面
├─ 子进程: 开发态 Vite (仅 isDev)                   127.0.0.1:5173
├─ BrowserWindow 渲染进程 (preload 暴露 desktopApi)
└─ 子进程: update-helper.js (仅 macOS 更新安装)
```

| 单元／公开入口 | 源码与装配位置 | 职责 | 通信／调用与生命周期 |
| --- | --- | --- | --- |
| Electron 主进程 | `package.json` 的 `main` → `electron/main.ts`（编译产物 `electron/main.js`） | 单实例、窗口、所属后端启停、共享对话框、Markdown 本地读取与打印、更新 | 由 `electron/dev-runner.js`（开发）或应用包启动；`before-quit`/窗口 `close` 经 `AppLifecycle` 协调后端停止后才退出 |
| 渲染进程 | `frontend/index.html` → `frontend/src/main.ts` | 工具页面、导航、设置 | 通过 `window.desktopApi` 调主进程；通过 `frontend/src/api/client.ts` 调 `127.0.0.1:18740` |
| 控制面后端 | `backend/src/toolbox_backend/main.py`，开发入口 `package.json` 的 `dev:backend`，打包入口 `backend/packaging/server.py` | 全部工具 API、设置、运行时控制、局域网控制面 | 仅监听 `127.0.0.1:18740`，`ControlAuthMiddleware` 校验 Bearer 凭据；随窗口关闭停止 |
| 局域网数据面 | `backend/src/toolbox_backend/modules/lan_transfer/server.py` + `web_app.py` | 供手机/平板浏览器上传下载文件 | 由控制面会话开启时启动独立线程与端口，会话关闭时设置 `should_exit` 并等待线程退出 |
| USB 工作子进程 | `backend/src/toolbox_backend/modules/usb_transfer/supervisor.py`，打包入口 `server.py --toolbox-usb-worker` | 唯一加载 libmtp 并执行设备读写的进程 | 由 `supervisor` 启动，stdin/stdout 走 `protocol.py` 的 JSON 行协议；延续应用所有权锁 |
| MinerU CLI | `backend/src/toolbox_backend/integrations/mineru.py` | PDF 深度解析与模型下载 | `subprocess.Popen`，进度靠 stdout/stderr 关键词；超时或取消时结束进程树 |
| update-helper | `electron/update-helper.ts` → extraResources `update-helper.js` | macOS 免签名更新包解压、校验、替换与重启 | 由 `mac-updater.ts` 以 `ELECTRON_RUN_AS_NODE` 启动，主进程退出后独立运行 |

## 关键数据流

### PDF 转 Markdown 深度解析

`PdfToMarkdown.vue` 上传文件 → `frontend/src/api/tools.ts` 的 `convertPdf(deep=true)` → `POST /api/v1/tools/pdf-to-markdown/convert` → `modules/pdf_to_markdown/deep_service.py` 校验并取得 MinerU 模型占用 → `subprocess.Popen` 启动 MinerU CLI，把阶段关键词写入任务目录的状态文件 → 前端轮询 `POST /progress` 读取该状态 → `POST /preview`、`POST /download` 由 `result.py` 读取任务目录并返回内容或文件。

受理即返回 `task_id`，转换完成以状态文件为准；取消与超时会结束子进程，模型占用在 `release_mineru_model_use` 释放。

### 有线传输任务

`UsbTransfer.vue` / `useUsbTransfer.ts` → `POST /tools/usb-transfer/tasks/prepare` 生成复制草稿 → `tasks/submit` 进入单会话 FIFO → `service.py` 交给 `executor.py` → `executor.py` 写前记录（`records.py`）后通过 `supervisor.py` 向 USB 工作进程下发逐项操作 → `worker.py` 调用 `mtp.py` 读写设备、`local_files.py` 处理本机侧 → 进度经协议回传，任务终态写回记录 → 前端轮询 `tasks/list`、`tasks/entries`。

API 进程不加载 libmtp；设备操作全部在子进程内。停止路径见 [有线传输](modules/usb-transfer.md)。

### 退出与安装协调

窗口 `close` 或 `before-quit` → `AppLifecycle.prepareClose` → `BackendRuntime.status()` 查询 `usb_active_tasks`/`usb_busy` → 有活动任务或状态未知时弹窗（默认留在应用）→ `POST /runtime/stop` → 后端 `lifecycle.request_shutdown` 停 USB 与投送会话并返回真实结果 → 确认后主进程发 SIGTERM 并等待退出，否则强杀并记录未确认。

## 状态与资源边界

| 数据／资源 | 权威维护者 | 位置或定义来源 | 访问及生命周期边界 |
| --- | --- | --- | --- |
| 用户数据根 | `electron/main.ts` 的 `resolveDataRoot`、`core/config.py` 的 `Settings.data_root` | 环境变量 `TOOLBOX_DATA_DIR`、命令行 `--toolbox-data-dir=`、平台默认目录 | 主进程启动后端时以环境变量传入；后端所有可写状态都在此目录下 |
| 应用所有权锁 | `core/runtime.py` 的 `acquire_ownership` | `Settings.ownership_lock_path`（固定在默认数据目录，不随数据根变化） | 非阻塞文件锁；USB 子进程通过描述符延续持有 |
| 控制面凭据 | `core/control_auth.py` 的 `initialize_control_token` | `Settings.runtime_dir/control-token` | 每次启动重新生成；主进程 `BackendRuntime.readToken` 校验 `instance_id`/`launch_id` 后才交给渲染进程 |
| 临时任务工作区 | `infrastructure/task_storage/workspace.py` 的 `TEMP_DIR`/`UPLOADS_DIR`/`get_task_dir` | `<data_root>/temp` | 各转换工具写入；启动时 `cleanup_expired_temp` 清理超期项 |
| 应用偏好 | `core/app_settings.py` | `<data_root>/settings.json` | 只保存用户显式设置过的字段（投送设备名、接收目录），临时文件加原子替换 |
| 局域网投送会话 | `modules/lan_transfer/session.py` 的 `sessions` | 内存 | 应用重启不恢复；凭据、预算、待确认队列、待取件清单都属于会话 |
| 局域网隔离区与接收记录 | `modules/lan_transfer/isolation.py`、`receive_log.py` | `<data_root>/lan_transfer`、接收目录、记录文件 | 上传先落隔离区，用户确认后才移入接收目录 |
| USB 状态记录 | `modules/usb_transfer/records.py` | `<data_root>/usb_transfer` | 写前意图 + 原子摘要 + 条目日志；不保存文件内容；启动时回收满足条件的完成记录 |
| MinerU 模型 | `modules/model_management/service.py` | `Settings.mineru_model_path`（默认 `<data_root>/resources/mineru`） | 由设置页下载；删除前需无下载任务与使用占用 |
| 证件照模型 | `modules/id_photo/model_resources.py`、`model_management.py` | `Settings.id_photo_model_path`：优先应用包内 `resources/id_photo`，否则 `<data_root>/resources/id_photo` | 随包资源只读；下载版位于数据目录，删除受使用占用约束 |
| 工具能力状态 | `core/capabilities.py` 的 `capabilities` | 内存 | 启动期探测 LibreOffice、证件照模型、USB 平台；设置页操作后由 `api/v1/settings.py` 同步刷新 |
| 更新状态 | `electron/update-state.ts` | 内存 + 广播 `updater:status` | 渲染进程订阅展示；macOS 下载产物与结果文件放在数据根 |

无数据库；除上表所列文件与内存状态外没有其他权威状态。

## 当前覆盖边界

- `backend/resources/` 下的模型二进制未纳入版本控制（`.gitignore` 的 `resources` 规则），而 `backend/packaging/backend.spec` 从磁盘整体收集该目录，`.github/workflows/desktop-release.yml` 没有准备步骤；因此出包是否带证件照与 MinerU 模型取决于构建机的本地文件，模型内容与来源只能通过 `backend/scripts/download_id_photo_models.py` 与 `model_management` 的下载逻辑确认。
- `electron/*.js` 是编译产物，本文只登记 `.ts` 源码；`package.json` 的 `main` 与 electron-builder 的 `files` 都指向 `.js`，两者行为一致性完全依赖 `npm run compile:electron` 先于启动/打包执行。
- 局域网数据面的浏览器页面（`modules/lan_transfer/web/`）是独立静态前端，未纳入 `frontend/` 的构建与类型检查，也没有独立类型声明；其接口契约只能对照 `web_app.py` 与 `app.js` 人工核对。
- `frontend/src/api/tools.ts` 单个文件承载 10 个工具的 HTTP 客户端（733 行），模块边界只在符号级存在，文件级无法按模块切分。
- `modules/model_management/service.py` 与 `modules/pdf_to_markdown/deep_service.py` 互相引用：前者删除模型时延迟导入后者停止执行器，后者又依赖前者登记模型占用；删除路径的副作用取决于执行器是否已启动。
- 更新链路的实际发布行为依赖 GitHub Release 资产，本文只描述源码可见机制。

## 维护边界

新增／移动文件时更新唯一归属；入口、运行职责、数据所有者或跨模块契约变化时同步相应模块与本页。局部实现变化未改变结构时不制造文档流水，不把未来方案写成现状。
