# 后端规范

> 后端开发规范由 skill `python-spec` 承载，通过 skill 按需加载对应模块的规范文件，避免全量读取。规范原文随 skill 分发，不依赖具体机器、操作系统或项目目录，可随 skill 在任意环境中使用。

## 使用方式

后端开发任务会自动触发 `python-spec` skill，skill 会根据任务类型按需加载对应的 reference 文件。

## 全局速查（通用规则）

1. 类型清晰：公共函数、边界模型和复杂返回值使用类型注解，不用 `Any` 掩盖问题
2. 边界校验：Pydantic 负责输入输出结构校验，业务规则与数据库查询不塞入 Schema
3. HTTP 语义正确：按资源操作选择 GET/POST/PUT/PATCH/DELETE 与适当状态码
4. 异常集中映射：领域/校验/认证/数据库/外部服务错误在合适边界统一转换，不在每个路由重复相同 `try/except`
5. 同步异步一致：不在 `async def` 中直接执行阻塞数据库、文件或网络操作
6. 安全默认：不泄露密钥、Token、SQL、文件路径和堆栈；上传、路径、URL、认证和权限在服务端校验
7. 迁移优先：数据库结构变化用项目已有迁移工具，不用运行时 `create_all()` 替代
8. 路径与文件：pathlib 与 os.path 均为标准库工具，延续项目既有风格，不做无价值转换
9. 日志：延续项目现有日志风格；参数化 `%s` 与 f-string 均可，不强制 f-string
10. 导入：优先清晰包名与模块导入，`层名_模块名` 别名仅在避免同名时使用
11. 认证：不默认 JWT，先识别项目实际认证方式（Cookie Session / Bearer JWT / OAuth / API Key）
12. 验证后交付：运行项目真实的格式、Lint、类型检查、测试、迁移检查与启动验证，如实报告结果

## 约定优先级

发生冲突时按以下顺序处理：

1. 用户本次明确要求
2. 仓库级指令与项目文档（如项目 CLAUDE.md）
3. `pyproject.toml`、锁文件、框架配置、数据库迁移、真实 API 契约和测试
4. 同模块现有代码和公共基础设施
5. skill 推荐规则

具体项目的特有约定（如统一响应格式、错误码体系、分层结构、分页字段名）属于第 2 层，由各项目文档自行声明，不在本通用规范中强制。
