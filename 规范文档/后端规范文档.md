# 后端规范

> 后端开发规范由 skill `python-spec` 承载，通过 skill 按需加载对应模块的规范文件，避免全量读取。规范原文随 skill 分发，不依赖具体机器、操作系统或项目目录，可随 skill 在任意环境中使用。

## 使用方式

后端开发任务会自动触发 `python-spec` skill，skill 会根据任务类型按需加载对应的 reference 文件。

## 全局速查（通用规则）

1. 新项目结构：默认采用最小 `src` 布局、按业务域纵向组织，并集中管理共享基础设施
2. 隐式命名空间包：不创建 `__init__.py`，构建工具需要时显式声明源码包
3. 文件创建条件：只有满足 `07-project-layout.md` 的明确条件时才新增文件，不创建空层
4. 类型清晰：公共函数、边界模型和复杂返回值使用类型注解，不用 `Any` 掩盖问题
5. 边界校验：Pydantic 负责输入输出结构校验，业务规则与数据库查询不塞入 Schema
6. API 方法统一：所有接口统一使用 POST，通过 Request Schema 和业务动作路径区分查询、列表、详情、创建、更新、删除和任务操作
7. 异常集中映射：领域、验证、认证、数据库和外部服务错误在合适边界统一转换
8. 同步异步一致：不在 `async def` 中直接执行阻塞数据库、文件或网络操作
9. 安全默认：不泄露密钥、Token、SQL、文件路径和堆栈
10. 开发期硬限制：不创建自动化测试、测试数据库、数据库迁移链、静态检查工具配置及缓存
11. Schema 直接重建：结构变化只更新当前 Model 或建表定义，不兼容旧结构
12. 删除必须授权：删除或重建数据库前提供绝对路径、原因、数据损失范围、重建步骤和检查方式，获得明确确认后才能执行
13. 路径与文件：pathlib 与 os.path 均为标准库工具，延续项目既有风格
14. 日志：记录关键事件和失败，不机械记录每个函数或步骤
15. 认证：不默认 JWT，先识别项目实际认证方式

## 约定优先级

发生冲突时按以下顺序处理：

1. 用户本次明确要求
2. 仓库级指令与项目文档（如项目 CLAUDE.md）
3. `pyproject.toml`、锁文件、框架配置、数据库定义和真实 API 契约
4. 同模块现有代码和公共基础设施
5. skill 推荐规则

具体项目的特有约定（如统一响应格式、错误码体系、分层结构、分页字段名）属于第 2 层，由各项目文档自行声明，不在本通用规范中强制。
